# 군집 모델 재점검 (2026-09-30)

맥도날드 9곳을 뺀 뒤 관광지 군집 수가 10 → 8(G), 10 → 7(GC)로 바뀐 것을 계기로, 군집 모델이 입력의 작은 변화에 얼마나 흔들리는지 점검했습니다. 기준 실행은 `analysis/outputs_cosine/run_20260929_234547_706228`입니다.

**방법**: `run_analysis.py`와 같은 후보 탐색(PCA KMeans·구면 코사인, k=2~10, 시드 3개, 시드 간 ARI 0.80·최소 군집 비율 0.02 조건)을 전체 행과 90% 부분표본(관광지 20회, 코스 30회)에 반복해 어느 k가 선택되는지 셌습니다. 그다음 k를 지금 값으로 고정하고 부분표본의 배정이 커밋된 배정과 얼마나 같은지(ARI, 군집별 Jaccard) 쟀습니다. 스크립트는 [`verification/k_selection_stability.py`](../verification/k_selection_stability.py), 수치는 [`verification/k_selection_stability.json`](../verification/k_selection_stability.json)입니다.

- 관광지 군집은 **"몇 개로 나누느냐"만 흔들리고, 장소들이 어떻게 묶이느냐는 흔들리지 않습니다.** k=8일 때 군집별 Jaccard는 G01 음식 1.00, G04 자연 0.99, G05 바다 1.00, G08 역사 0.96입니다. 경계가 흐린 곳은 체험을 체류시간으로 나눈 G02(0.71)·G03(0.90)과 긴 체류 혼합 G06(0.85)입니다.
- 맥도날드 삭제 전 k=10과 삭제 후 k=8은 둘 다 실루엣이 거의 같은 후보 중 하나입니다(k=6~10의 실루엣 0.702~0.718, 차이 0.016). 9곳(0.4%)을 빼자 최대값이 k=10에서 k=8로 옮겨 갔을 뿐입니다.
- 추천 결과에는 영향이 없습니다. 추천은 군집 번호를 쓰지 않고 선호 벡터와 코스 범주 비중을 직접 비교합니다. G·GC 군집은 코스의 관광지 구성 표(`citytour_G_composition_shares.csv`)와 지도 같은 설명용 결과에만 쓰입니다.

## 왜 관광지 군집 수가 흔들리는가

관광지 특징은 범주(원핫 5개)·기준 체류시간·유네스코 표식뿐이라, 2,540곳의 특징 조합은 **86가지**뿐입니다(코스는 234개 중 180가지). KMeans는 사실상 86개 점을 가중치(장소 수)를 두고 나누는 셈이고, 범주가 다르면 벡터가 거의 직교하므로 "범주별로 하나씩"(k=5)까지는 실루엣이 가파르게 오르고 그 뒤는 **같은 범주 안에서 체류시간을 몇 단계로 자르느냐**의 문제가 됩니다. 어느 범주를 먼저 자르든 실루엣 차이는 0.01 안팎이라, 소수 장소의 유무로 최대값이 옮겨 다닙니다.

## 권고

1. **당장 바꿀 것은 없습니다.** 군집 수 변동은 설명용 결과의 번호와 개수만 바꾸고, 배정 구조와 추천은 그대로입니다. 명세서 21장·25장과 README 11절에 이미 "k=7~10의 실루엣 차이가 0.01 안팎이라 입력이 조금만 바뀌어도 선택 k가 달라질 수 있다"고 적어 두었습니다.
2. 관광지 군집 수를 실행마다 다시 정하는 대신 **고정하는 방안**을 검토할 수 있습니다. 관광지 특징 구조상 k는 "범주 5개 + 체류시간 단계"로 정해지므로, 설계값으로 못 박는 편이 실행 간 비교에 유리합니다. 다만 값을 정하려면 어떤 단계 구분(예: 역사·체험을 짧은 방문/보통 방문으로 나눌지)을 원하는지 결정이 필요합니다.
3. 코스 군집(T·TC)은 지금 규칙으로 충분히 안정적이므로 그대로 둡니다.
4. 부분표본 점검은 입력을 바꿀 때마다 같이 돌리는 것을 권합니다(`python verification/k_selection_stability.py <tables>/G_features.csv 20 0.9 out.json`, 관광지 약 15분).
